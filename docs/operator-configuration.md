# Operator configuration

ParkBench host commands select `.env.local` by default. Set `PARKBENCH_ENV_FILE` in the invoking process to select another file; relative file names are resolved from the repository root. For every setting present in both the invoking process and the selected file, the process value wins. The shared loader reports the key and source labels for differing values without printing either value. ParkBench follows the Docker CLI target selected by the operator without checking its context name; setup and runtime compare Docker Engine IDs to detect an Engine change.

Relative host paths use the ParkBench repository root, regardless of the caller's working directory. Existing symlinks are resolved before containment and mapping checks. Compose uses fixed paths inside containers (shown in the consumer column); direct-host path values remain meaningful for running the control plane directly. A container-only path is derived from the mounted host data root and is not independently configurable in Compose.


## Database writer capabilities

For a database verified to support APWs and BIW, declare the capability in the active operator profile:

```dotenv
PARKBENCH_OPENEDGE_DB_FEATURES=enterprise
```

The default is empty. ParkBench does not infer licensed capabilities from an image name such as `_ent` or inspect a license during scheduling. An empty feature list therefore blocks requests for positive APW counts or an enabled BIW even when the selected image supports them. The scheduling error names the missing setting; it is not a native license rejection. APW zero and BIW false remain available without this declaration.

After changing the setting, recreate the control plane using `node scripts/run-with-env.mjs bash scripts/start.sh --no-build --force-recreate`. Changes to the host file alone do not update an already-created container's environment. Process environment values take precedence over the selected file, including an explicitly empty process value. Check `/api/v1/ui-options`: `databaseParameters.features` must include `enterprise` before scheduling writers.

The declaration enables scheduling; each run still starts the requested writers and verifies native database connection membership before measurement. It does not grant a license or bypass native startup failures. If the database image or license changes, verify support again and update the declared feature list.


## Buffer hash table latch factor

`-hashLatchFactor` is a supported primary database broker startup parameter. It specifies the number of buffer hash-table latches as a percentage of the table entries: minimum **5%**, maximum **100%**, default **10%**, with whole-number inputs. OpenEdge rounds the calculated latch count down and allocates at least two latches. The count is fixed when the primary broker starts and cannot be changed online. `-hash` sets the table size; `-hashLatchFactor` sets its latch allocation percentage.

Choose it in a fixed startup parameter or matrix dimension. The selector shows a short purpose; its help contains the detailed explanation, limits and default with an [official OpenEdge 12.8 reference](https://docs.progress.com/bundle/openedge-startup-and-parameter-reference-128/page/Buffer-Hash-Latch-Factor-hashLatchFactor.html). An omitted value remains controlled by native startup defaults; ParkBench does not inject the documented default. Native reporting remains unverified until observation is available; adding this catalog entry did not involve starting an experiment or database.

## Feature 017 observer defaults

Fresh licensed image configuration selects `/app/openedge/observers/db/parkbench-db-observer-v2.r`. Raw launches without a procedure override select `/app/openedge/observers/db/prepare-run-db-observer.p`; that procedure prepares only the packaged v2 source for the connected database. Both modes preserve normal protocol 3 and parameter capture v1. Compiled v2 must match the runtime schema.

Rebuild generic before final (or all) and refresh generated `images.env` using the existing workflow. Explicit procedure overrides still win; replace a deliberately configured legacy selection when adopting v2. Private `.env.local` is not rewritten by this feature. The original source and legacy adapter approvals remain available.

`PARKBENCH_OBSERVER_READ_ONLY=true` and the existing command/connection settings remain required. Exact packaged paths do not create host mounts. External approved sources retain existing host existence and lexical read-only checks; the bootstrap is not an arbitrary compiler entrypoint. Collection timeout/output caps remain 5 seconds/8 MiB normally and 10 seconds/2 MiB for capture.
